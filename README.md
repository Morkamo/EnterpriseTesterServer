# EnterpriseTester Dedicated Server

Отдельный solution .NET 10 Console Application для Rider. Управляет существующим Java/Spring Boot backend EnterpriseTester. Исходный web-app, desktop и Android не редактируются. Схема MySQL только проверяется; создание таблиц, SQL-инициализация, Flyway/Liquibase отключены.

## Быстрый запуск Windows

Git содержит исходники запускателя и небольшой `backend/backend.json` с контрольной суммой версии Java backend. Сам JAR (около 77 МБ) в Git не хранится.

Для развёртывания переносите готовый пакет из `artifacts/EnterpriseTesterServer-win-x64.zip` либо `artifacts/EnterpriseTesterServer-linux-*.tar.gz`: он уже содержит и запускатель, и `backend/EnterpriseTester.jar`, и `backend/backend.json`. Импорт web-проекта на целевом устройстве не нужен.

Если запускать именно клонированные исходники, один раз скопируйте `backend/EnterpriseTester.jar` из соответствующего готового пакета в каталог `backend` клона. Версии JAR и `backend.json` должны совпадать. Проверка без Java и БД: `dotnet run --project EnterpriseTester.ServerHost -- verify-backend`. Один `git clone` не доставляет исполняемый Java backend. Пакеты сборки передаются отдельно от Git (например, как артефакты релиза).

Рабочий `config/server.json`, пароли, изображения и установленные runtime в Git не хранятся: на другом устройстве нужно настроить подключение к существующей БД.

В этой рабочей папке откройте `StartServer.bat`. Консоль проверит MySQL, Java и JAR, покажет журнал и адреса. Здесь подготовлен приватный `config/server.json` с локальным подключением из ранее сохранённых настроек. Пароль не показывается в консоли.

В переносимом пакете `win-x64` запуск такой же. .NET уже включён. При первом запуске создаётся конфиг и открывается мастер настройки существующей БД. Java 21+, если не найдена, автоматически скачивается из официального Adoptium в папку runtime, SHA-256 проверяется, распаковка и прогресс видны в консоли. Системная Java и JAVA_HOME не меняются.

- `ConfigureServer.bat` — мастер настроек.
- `CheckServer.bat` — диагностика БД, схемы, Java и контрольной суммы backend.
- `StopServer.bat` — остановка своего запущенного backend.
- `ManageServer.bat status` — проверить ответ приложения.

Ctrl+C в главной консоли останавливает запускатель. Linux получает SIGTERM для штатной остановки; на Windows при необходимости после таймаута процесс завершается принудительно. Не закрывайте окно крестиком как штатный способ остановки: используйте Ctrl+C или StopServer.

## Linux

Распакуйте пакет нужной архитектуры, откройте терминал в его папке:

```bash
chmod +x app/EnterpriseTesterServer *.sh
./start-server.sh
# управление из другого терминала
./manage-server.sh doctor
./manage-server.sh status
./stop-server.sh
```

.NET включён; SDK не требуется. Пакеты linux-x64/linux-arm64 предназначены для Linux с glibc (Ubuntu/Debian и совместимые системы). Для отсутствующих системных библиотек предусмотрен `sudo bash install-linux-dependencies.sh` (apt/dnf). Java устанавливается локально без root. Обычная работа сервера не требует root.

Новая MySQL, новая база или SQL-дамп автоматически не устанавливаются/не импортируются. Используется ваша существующая локальная или удалённая MySQL. Запускатель может запустить уже установленную локальную службу (`MySQL80` на Windows, `mysql` на Linux); для системной службы могут потребоваться отдельные административные права. Настройте `Database.LocalServiceName`, если служба называется иначе. На новом сервере установите MySQL отдельно и восстановите существующую базу своим согласованным способом либо подключитесь к удалённой базе.

## Конфигурация

Рабочий файл: `config/server.json`. Пример без секретов: `config/server.example.json`. JSON допускает комментарии и завершающие запятые. Неизвестные поля отклоняются, чтобы опечатки не меняли подключение молча.

Основные поля:

| Поле | Назначение |
|---|---|
| Database.Host / Port | Адрес MySQL, обычно 127.0.0.1:3306 |
| Database.Name | Имя существующей базы enterprisetesterdb, не путь к SQL-файлу |
| Database.User / Password | Пользователь и пароль MySQL |
| Database.SslMode | Preferred локально; VerifyFull для удалённой MySQL |
| Server.BindAddress | 0.0.0.0 — доступ из локальной сети; 127.0.0.1 — только этот ПК |
| Server.Port | Порт приложения, по умолчанию 8080 |
| Server.ImagesDirectory | Существующий каталог изображений или копия data/questions |
| Runtime.JavaExecutable | Путь к Java 21+; пусто — автоматический выбор |
| Runtime.AutoDownloadJava | Скачивание Java при её отсутствии |
| Runtime.MaxRestarts | Лимит перезапусков при неожиданном завершении, по умолчанию 0 |

Пароль можно хранить непосредственно в конфиге, как запрошено, либо указать `"Password": "${ENV:ENTERPRISE_TESTER_DB_PASSWORD}"`. Рабочий конфиг исключён из Git и публичных пакетов. Мастер ограничивает доступ к файлу текущей Windows-учётной записью/System; на Linux использует 0600. При ручном копировании также задайте `chmod 600 config/server.json`. Не публикуйте рабочий конфиг. В консоли/логах пароль маскируется и не передаётся в аргументах Java.

Для HTTPS: `Server.TlsEnabled=true`, путь PKCS12 в `KeyStorePath`, пароль/переменная окружения в `KeyStorePassword`, а в `HealthHost` — имя/IP из сертификата, доступное серверу. Сертификат должен быть доверенным клиентским устройствам и соответствовать адресу. Для удалённой БД VerifyFull проверяет TLS и имя сервера. Собственный CA можно задать PEM-файлом в `Database.CaCertificatePath`: он используется проверкой MySQL и импортируется в локальное доверенное хранилище JVM (нужен JDK/keytool; install-java получает JDK). Отдельные тестовые подключения допускают `AllowInsecureRemote=true` по явному выбору. Для эксплуатации используйте пользователя MySQL с нужными правами на данные, без прав изменять схему.

Изображения хранятся отдельно от MySQL: для переноса вместе с изображениями нужны и база, и файлы. В текущем пакете подготовлена копия файлов исходного приложения. Если исходный сайт запускается отдельным процессом с той же БД, используйте общий каталог изображений. Публичные архивы не содержат ваших изображений. Если каталог отсутствует, он создаётся; если он пуст, а в БД есть ссылки на изображения, выводится предупреждение, но сервер продолжает запуск. Потерянная картинка недоступна (HTTP 404), остальные данные и функции продолжают работать. Файлы можно восстановить позже без изменения БД.

## Клиенты

Desktop на этом ПК использует `http://localhost:8080/` и обнаруживает уже работающий backend, не запуская второй. Android по Wi-Fi использует IP ПК, например `http://192.168.8.97:8080/`, и локальный режим HTTP. IP может измениться. Сервер выводит адреса интерфейсов; выберите физический Ethernet/Wi-Fi, а не VPN/виртуальный адаптер.

Для desktop на другом ПК или работы через интернет настройте HTTPS и укажите адрес в клиенте. Приложения не ищут сервер по всей сети. Не открывайте MySQL наружу для клиентов. Брандмауэр и роутер этот пакет не перенастраивает: разрешите порт приложения только в нужной сети.

## Обновление и разработка

Форматирование исходников задано в `.editorconfig` и `.csharpierrc.json`. Для C#/XML закреплена версия CSharpier в `.config/dotnet-tools.json`. Из корня решения:

```powershell
dotnet tool restore
dotnet csharpier format .
dotnet csharpier check .
```


```powershell
dotnet build EnterpriseTesterServer.sln -c Release
dotnet test EnterpriseTester.ServerTests -c Release
dotnet run --project EnterpriseTester.ServerHost -c Release -- verify-backend
dotnet run --project EnterpriseTester.ServerHost -c Release -- import-backend --source 'путь-к-новому-JAR'
./scripts/Publish.ps1
```

Импорт нужен при намеренном обновлении Java backend. Он читает JAR, копирует в эту папку и удаляет встроенные параметры доступа к БД из копии. Исходный JAR не меняется. Контрольная сумма фиксируется в backend/backend.json и проверяется при запуске. После обновления включайте новый backend.json в коммит и пересобирайте переносимые пакеты командой `scripts/Publish.ps1`. JAR остаётся в пакетах сборки, а не в истории Git. Не подменяйте JAR во время работы: остановите сервер, выполните импорт и запустите заново. Сохраняйте config, data и runtime при обновлении пакета.

Команды CLI: start, configure, create-config, setup-local (Windows: импорт ранее сохранённого DPAPI-пароля desktop без его изменения), doctor, status, stop, install-java, import-backend, verify-backend. Последняя проверяет комплектность и контрольную сумму JAR без Java и подключения к БД. `--root` задаёт папку пакета; `--config` — другой конфиг; `--non-interactive` отключает чтение команд из консоли. Журналы находятся в logs. Результаты фактических проверок — docs/verification.md.
